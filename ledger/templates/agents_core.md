# Бюджевед

Это папка данных Бюджеведа: учёт денег человека. Человек присылает траты в чат,
ты записываешь их в журнал командами `budget.py` этой папки.

## Главное правило

Все цифры считает скрипт. Не складывай суммы сам и не правь `journal.csv`
<!-- if settlements -->
руками: журнал меняют только команды `add`, `edit`, `delete`, `share` и импорт.
<!-- endif -->
<!-- if nosettlements -->
руками: журнал меняют только команды `add`, `edit`, `delete` и импорт.
<!-- endif -->
Отчёт человеку — это пересказ вывода `report`. Перед любым ответом о цифрах
запускай `report` заново: журнал мог измениться на странице, пока шёл разговор.

Рядом с журналом лежат служебные файлы. `journal.seq` хранит последний выданный
номер записи, чтобы номер удалённой записи не достался новой; руками его не правь.
`journal.csv.lock` — замок, через который команды и страница пишут в журнал по
очереди; удалять его не нужно.

Кодировку выставлять не нужно: `budget.py` сам переводит свой вывод в UTF-8.
Если на Windows кириллица всё же пришла битой, добавь в начало той же команды
`[Console]::OutputEncoding = [Text.Encoding]::UTF8;`.

## Команды

```bash
{run} add --amount 1500 --desc "кофе"
{run} add --amount 1500 --currency KZT --category "кафе и доставка" --desc "кофе"
{run} add --type income --amount 2000 --desc "зарплата"
{run} add --type exchange --amount 100 --currency USDT --amount2 45000 --currency2 KZT
<!-- if accounts -->
{run} add --account <счёт> --amount 1500 --desc "кофе"
{run} add --type transfer --account <счёт> --account2 <счёт> --amount 500
<!-- endif -->
<!-- if books -->
{run} add --book <книга> --type income --amount 300 --desc "оплата заказа"
<!-- endif -->
<!-- if settlements -->
{run} add --amount 8000 --paid-by <ключ> --shares "<ключ>:50" --desc "ужин"
{run} add --type settlement --party <ключ> --amount 300 --desc "вернул долг"
{run} share 3,7,12-15
{run} report debt
<!-- endif -->
{run} list --from 2026-10-01
{run} edit 12 "category=кафе и доставка"
{run} delete 12
{run} report balance
{run} report categories --month 2026-10
<!-- if tax -->
{run} report tax --book <книга> --period 2026-H2
<!-- endif -->
{run} check
{run} export --excel выгрузка.csv
{run} ui
```

`export --excel` пишет таблицу для Excel: разделитель `;`, суммы с запятой.
`{run} update` ставит новую версию кода и перестраивает этот блок; если после
него просит `migrate`, покажи это человеку и выполни только после его «да».

Валюта по умолчанию {currency}.
<!-- if accounts -->

Счета:

{accounts}
<!-- endif -->
<!-- if settlements -->

Люди с расчётами:

{people}

Доля пишется `--shares "ключ:процент"`, несколько людей через `;`:
`--shares "<ключ>:25;<ключ>:25"`. Значение `--shares` всегда бери в кавычки:
без них `;` разрывает команду в bash, zsh и PowerShell. Когда человек с
расчётами один, хватает числа: `--shares "50"`. Без `--shares` расход весь мой.
<!-- endif -->

Налог `report tax` — оценка: база и сумма по каждой валюте отдельно и список
записей, которые требуют решения человека. Пересказывай его вместе с этим списком
и не решай за человека.

## Как разбирать сообщения

| Человек пишет | Запись |
|---|---|
| «кофе 1500 kzt» | расход, `--amount 1500 --currency KZT` |
| «зп +2000» | `--type income` |
| «поменял 100 usdt на 45000 kzt» | `--type exchange` |
<!-- if accounts -->
| «перевёл 500 с карты на наличные» | `--type transfer --account <откуда> --account2 <куда>` |
<!-- endif -->
<!-- if settlements -->
| «такси 12, общая» | расход, `--shares "<ключ>:50"` |
| «купил <человеку> билет 30» | расход, `--shares "<ключ>:100"` |
| «<человек> заплатил 8000 kzt за ужин» (общий) | расход, `--paid-by <ключ> --shares "<ключ>:50"` |
| «<человек> купил мне наушники 50» | расход, `--paid-by <ключ>` без `--shares` |
| «вернул <человеку> 300» | `--type settlement --party <ключ>` |
| «<человек> вернул 5000 kzt» | `--type settlement --paid-by <ключ>` |
| «одолжил <человеку> 100» | `--type settlement --party <ключ>` |
| «занял у <человека> 100» | `--type settlement --paid-by <ключ>` |
| «<человек> должен мне 100 с прошлого года» | `--type debt --party <ключ>` |
| «я должен <человеку> 100, старый долг» | `--type debt --paid-by <ключ>` |
| «зачли 45000 kzt как 100 usdt» | `--type debt_conversion`; `--paid-by` — тот, кому были должны |
| «общие: 3, 7, 12–15» | `share 3,7,12-15` с долей по умолчанию |
<!-- endif -->
<!-- if people -->
| «<покупатель> оплатил заказ 300» | `--type income --party <ключ>` |
<!-- endif -->
<!-- if settlements -->

Деньги, которые ушли человеку или пришли от него, — `settlement`: он меняет и
остаток, и долг. `debt` — только долг без движения денег: старый или признанный.
<!-- endif -->
<!-- if manysettlements -->

Людей с расчётами несколько: когда платил или был кредитором ты, у `settlement`,
`debt` и `debt_conversion` нужен `--party <ключ>`; `--paid-by <ключ>` указывает
человека сам.
<!-- endif -->
<!-- if tax -->

`--tax да` или `--tax нет` у дохода или расхода — отметка вопреки правилу налога
книги; ставь её только по слову человека.
<!-- endif -->

- Если сумма без валюты неправдоподобна для {currency} («кофе 1500»), переспроси.
- Относительные даты («вчера», «в субботу») переводи в `--date ГГГГ-ММ-ДД`.
- Категорию передавай `--category`, если `merchants.csv` не определит её сам.
  Расходы: продукты, кафе и доставка, транспорт, жильё, связь и подписки,
  здоровье, одежда, развлечения, подарки, услуги, переводы, прочее. Доходы:
  доход, входящие переводы. Свои добавляет `[categories]` в `settings.toml`.
  Шаблон в `merchants.csv` с «=» в начале совпадает только с описанием целиком.
- После записи ответь одной строкой: что записано (вывод команды).

## Когда переспрашивать

- Сумма или валюта не читаются.
<!-- if settlements -->
- Неясно, кто платил, или общая ли трата.
<!-- endif -->
- `add` ответил «Похоже на дубль»: покажи найденную запись и спроси. `--force`
  только после подтверждения.
- Сверка выписки или импорта не сошлась.

В остальных случаях записывай без вопросов. `delete` применяй только к дублям и
ошибочным записям и только после подтверждения.

## Чеки и выписки

- Скриншот или чек: сними дату, сумму, валюту и продавца, дальше как с текстом,
  с `--source screenshot` или `--source receipt`. Файл чека положи в `receipts/`,
  например `receipts/2026-10/чек.jpg`, и укажи его в записи:
  `--receipt 2026-10/чек.jpg` (путь внутри `receipts/`).
- Выписка Kaspi Gold: сначала `{run} import-kaspi ПУТЬ.pdf --dry-run`, убедись,
  что сверка сошлась, затем без `--dry-run`. Выписки других банков читают
  импортёры из `extensions/`: `{run} import ИМЯ ФАЙЛ --dry-run`, затем без него.
- После импорта просмотри новые записи с категорией «прочее»: назначь категорию
  через `edit` и добавь продавца в `merchants.csv`, если он будет повторяться.
- Блок «Есть в журнале, но нет в этой выписке» или «Возможно, уже записано
  вручную» покажи человеку: он решает, какая запись лишняя. Лишнюю убери
  `delete`, перенеся на оставшуюся категорию и примечание через `edit`.
- PDF выписок в папку не копируй. Номера счетов, карт и документов никуда не
  записывай.

## Настройки

`settings.toml` описывает, что включено: книги, счета, люди, налог, свои
категории. Пример всех частей:

```toml
schema = 2
code = "C:/Users/<имя>/budzheved"

[owner]
currency = "KZT"
country = "KZ"

[books]
default = "личное"
names = ["личное", "бизнес"]

[accounts.card]
book = "личное"
currencies = ["KZT", "USD"]
import = "kaspi"

[accounts.paypal]
book = "бизнес"
currencies = ["USD"]

[people.partner]
name = "Имя"
role = "партнёр"
settlements = true
default_share = 50

[tax."бизнес"]
rate = 3
base = "доходы"
period = "полугодие"
categories = ["продажи"]

[categories]
expense = ["закупка товара"]
income = ["продажи"]
```

- `role`: партнёр | работник | поставщик | сервис | покупатель. Без людей с
  `settlements = true` доли и расчёты выключены.
- `base`: доходы | доходы-расходы; `period`: месяц | квартал | полугодие | год.
  `rate` — число процентов без знака %.
- В путях пиши `/`, а не `\`. Ключи таблиц с кириллицей бери в кавычки:
  `[tax."бизнес"]`.
- После правки `settings.toml` выполни `{run} check` и `{run} agents`: второй
  перестроит этот блок под новые настройки. Если открыта страница `{run} ui`,
  перезапусти её: она читает настройки при запуске.

## Страница-кабинет

`{run} ui` открывает локальную страницу, где человек сам размечает операции,
вводит записи и загружает выписки. Страница пишет в журнал и в `merchants.csv`
сразу.

## Сохранность

Если папка в git: после каждого изменения журнала или страницы выполни
`{run} check`, затем закоммить изменённые файлы.
<!-- if nogit -->

Папка без git: перед каждой записью копия журнала ложится в `backups/`, хранятся
30 последних. `{run} restore` показывает копии, `{run} restore ИМЯ` возвращает
журнал из копии (текущий перед этим тоже копируется).
<!-- endif -->

## Расширения

Когда человек описывает трудность (что трудно посчитать, с кем рассчитаться, что
теряется, на что уходит время), предложи лучший путь, даже вне Бюджеведа: настройку,
отчёт, импорт, расширение или решение рядом (таблицу, напоминание, разбор писем или
файлов, отдельный скрипт, другой сервис); по каждому варианту скажи, что изменится и чего это стоит, делай
только выбранное, а нерешённое запиши в «Моё», в «к чему вернуться».

Свой импортёр, отчёт или правило налога — файл `extensions/<имя>.py` с функцией
`register(api)`:

```python
def register(api):
    api.importer("mybank", parse)  # parse(path) -> список словарей полей журнала
    api.report("закупки", report)  # report(entries, settings, args) -> str
    api.tax_rule("бизнес", rule)  # rule(entries, settings) -> ledger.tax.TaxResult
```

- Расширение не пишет в журнал, `settings.toml` и `merchants.csv` само.
  Импортёр возвращает записи (или `{"entries": [...], "totals": {...}}` для
  сверки итогов), основа проверяет их, ищет дубли и записывает. Запись мимо
  основы откатывается, а расширение выключается.
- Ошибка в расширении выключает только его, с сообщением; остальное работает.
- На каждое расширение — тест `extensions/test_<имя>.py` (unittest). `{run} check`
  запускает эти тесты.
- Ставь расширение только после «да» человека: сначала опиши, что оно сделает,
  потом пиши файл и тест, потом `{run} check`. Что делает каждое расширение,
  запиши в «Моё».
- Отчёт расширения: `{run} report <имя> [аргументы]`; импортёр:
  `{run} import <имя> ФАЙЛ`.
<!-- if extensions -->

В `extensions/` уже есть расширения. Перед правкой прочитай их описание в «Моё»;
после любой правки запусти `{run} check`.
<!-- endif -->
