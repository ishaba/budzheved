# Бюджевед

Учёт денег с агентом. Вы пишете агенту в чат, как обычному помощнику: «кофе 1500»,
«клиент заплатил 300 долларов на PayPal», «поменял 100 USDT на тенге». Агент
записывает операции в журнал, а все цифры считает скрипт: остатки, расходы по
категориям, долги между людьми, оценку налога. Агент только вызывает команды и
пересказывает их вывод, сам он суммы не складывает.

Код общий, данные у каждого свои: журнал, настройки и правила агента лежат в
отдельной папке данных. Её можно назвать как угодно, в том числе по-русски и с
пробелами.

## Что нужно

- Python 3.11 или новее. Других зависимостей нет.
- Агент, который умеет запускать команды на компьютере: Codex, Claude Code или
  похожий.
- По желанию git. С ним код обновляется через `git pull`; без него код берётся
  архивом выпуска, а журнал перед каждой записью копируется в `backups/`.

Работает на Windows, macOS и Linux.

## Начать одним промптом

Откройте Codex или Claude Code в любой папке и вставьте промпт ниже целиком. Агент
проверит, что стоит на компьютере, возьмёт код, создаст папку данных и расспросит
вас о деньгах по одному вопросу. Ничего не ставит и не меняет без вашего «да».

```text
Помоги мне начать учёт денег в Бюджеведе: https://github.com/ishaba/budzheved.
Это программа на Python. Журнал операций лежит в CSV, а все цифры считает её
скрипт; ты только вызываешь его команды и пересказываешь вывод. Сам суммы не
складывай.

Как со мной работать:
- Задавай по одному вопросу за раз и жди ответа. Говори просто, без жаргона.
- Ничего не ставь, не скачивай и не меняй вне папок Бюджеведа без моего «да».
- Номера карт, счетов и документов никуда не записывай.

Шаг 1. Проверка.
Узнай, какая у меня система. Проверь Python 3.11 или новее (на Windows
`py --version`, иначе `python3 --version`) и git (`git --version`). Если
чего-то нет, скажи, чего именно и зачем оно нужно, и предложи поставить. На
Windows после моего «да», по одной программе:
`winget install Python.Python.3.13 --source winget --accept-package-agreements --accept-source-agreements`
и `winget install Git.Git --source winget --accept-package-agreements --accept-source-agreements`.
Если Windows спросит разрешение, скажи мне подтвердить окно. После установки
открой новый терминал, чтобы команда нашлась. Если я не хочу git, это нормально:
тогда код берётся архивом, а журнал перед каждой записью копируется в папку
backups.

Шаг 2. Код и папка данных.
Спроси отдельными вопросами: в какой валюте я чаще всего считаю (код из трёх
латинских букв, например EUR, или USDT); потом в какой стране веду дела (код из
двух букв, например DE). Потом предложи две папки рядом: для кода, например
`budzheved` в моей домашней папке, и для данных, например `Мои деньги` там же.
Папка данных лежит рядом с папкой кода, а не внутри неё. Пути всегда бери в
кавычки: в них бывают пробелы и кириллица.
- Есть git: `git clone https://github.com/ishaba/budzheved.git "<папка кода>"`.
- Нет git: возьми архив последнего выпуска через GitHub API. Папки кода ещё не
  должно быть: если она есть, `Move-Item` положит код внутрь неё, поэтому сначала
  проверь (`Test-Path "<папка кода>"`) и, если папка есть, спроси меня, что с ней
  делать. На Windows в PowerShell:
    $r = Invoke-RestMethod https://api.github.com/repos/ishaba/budzheved/releases/latest
    Invoke-WebRequest $r.zipball_url -OutFile "$env:TEMP\budzheved.zip" -UseBasicParsing
    Remove-Item "$env:TEMP\budzheved-zip" -Recurse -Force -ErrorAction SilentlyContinue
    Expand-Archive "$env:TEMP\budzheved.zip" "$env:TEMP\budzheved-zip" -Force
    Move-Item (Get-ChildItem "$env:TEMP\budzheved-zip" -Directory)[0].FullName "<папка кода>"
  На macOS и Linux то же самое: `zipball_url` из того же адреса, `curl -L` и
  `unzip`, единственную папку из архива переименуй в `<папка кода>`.
Затем создай папку данных:
`py "<папка кода>/budget.py" --data "<папка данных>" init --currency <валюта> --country <страна>`
(не на Windows вместо `py` пиши `python3`). Дальше все команды выполняй из папки
данных: `py budget.py <команда>`. Команды на Windows идут в PowerShell.
Выставлять кодировку не нужно: `budget.py` сам переводит свой вывод в UTF-8.
Если кириллица всё же пришла битой, добавь в начало той же команды
`[Console]::OutputEncoding = [Text.Encoding]::UTF8;`: каждая твоя команда идёт
в новом запуске PowerShell, и настройка из прошлой команды не сохраняется.
Прочитай `AGENTS.md` в папке данных: там правила и все команды.

Шаг 3. Анкета, по одному вопросу:
1. Какой у меня налоговый режим: какая ставка, с доходов или с доходов минус
   расходы, за какой период платится. Не знаю — это пойдёт в «к чему вернуться».
2. Нужно ли вести деньги раздельно, например личное и бизнес (это книги).
3. Где лежат деньги: банки, карты, PayPal, наличные, крипта (это счета).
4. Какие валюты на каждом счёте.
5. Есть ли работники.
6. Какие поставщики и сервисы.
7. Нужны ли взаиморасчёты и с кем: с кем я делю траты, кто платит за меня, кому
   я одалживаю.
8. Какие цифры я хочу видеть и как часто.

Шаг 4. Что сейчас трудно.
Спроси, что сейчас трудно с подсчётами и расчётами: что трудно посчитать, с кем
трудно рассчитаться, что теряется, на что уходит время. По каждой трудности
предложи два-три варианта. Не ограничивайся Бюджеведом: выбери самое подходящее
из того, что умеешь сам. Это может быть настройка, отчёт, импорт или расширение
Бюджеведа, а может быть решение рядом с ним: таблица, напоминание, разбор писем
или файлов, отдельный скрипт, другой сервис. По каждому варианту скажи, что
изменится в моей работе и чего это стоит: времени, денег, усилий. Спроси, что мне
удобнее. Выбранное войдёт в план шага 5; до «да» на план ничего не делай. То, что
не решили, тоже войдёт в план: после «да» оно ляжет в `AGENTS.md` папки данных, в
раздел `## Моё`, под заголовок «к чему вернуться».

Шаг 5. План.
Покажи план одним списком: книги, счета, люди, налог, расширения, решения из
шага 4 и «к чему вернуться». После моего «да» дополни `settings.toml`, который
создал `init`: `schema`, `code` и `[owner]` не меняй, остальные части бери из
образца в разделе «Настройки» файла `AGENTS.md`. Ключи таблиц с кириллицей бери в
кавычки: `[tax."бизнес"]`. Затем выполни `py budget.py check` и
`py budget.py agents`. Сделай выбранное в шаге 4. Свои договорённости, что делает
каждое расширение, и «к чему вернуться» запиши в раздел `## Моё` файла
`AGENTS.md`, ниже блока основы; внутри блока основы ничего не правь.

Шаг 6. Проба.
Попроси у меня одну трату и запиши её командой `add`. Покажи
`py budget.py report balance` и `py budget.py report categories`, потом
выполни `py budget.py check`. Если запись была пробной, удали её командой
`delete` после моего «да». Расширение ставь только после моего «да» и только с
тестом в `extensions/test_<имя>.py`; `check` запускает эти тесты.

Налог: `report tax` даёт оценку, а не декларацию. Пересказывай её вместе со
списком записей, которые требуют решения, и не решай за меня. Ставку и правила
режима я сверяю сам.

В конце коротко скажи, что настроено, что записано в «к чему вернуться» и как
дальше: открыть тебя в папке данных и писать траты в чат.
```

После первого запуска открывайте агента в папке данных: он прочитает `AGENTS.md`
и будет записывать траты по сообщениям.

## Как это устроено

- **Папка кода** — этот репозиторий: `budget.py` и `ledger/`. Её можно обновлять,
  данных в ней нет.
- **Папка данных** создаётся командой `init`:
  - `journal.csv` — журнал операций;
  - `settings.toml` — валюта, книги, счета, люди, налог, свои категории;
  - `AGENTS.md` — правила для агента: блок основы, который строится по
    настройкам, и ваш раздел `## Моё`;
  - `merchants.csv` — правила категорий по продавцам;
  - `budget.py` — запуск, который находит код по пути `code` из `settings.toml`;
  - `receipts/`, `extensions/`, `backups/` — чеки, расширения, копии журнала.

Команды выполняются из папки данных: `py budget.py <команда>` на Windows,
`python3 budget.py <команда>` на macOS и Linux.

| Команда | Что делает |
|---|---|
| `init --currency KZT --country KZ` | создаёт папку данных; запускается из папки кода с `--data <папка>` перед `init` |
| `add --amount 1500 --desc "кофе"` | добавляет запись; `--type`, `--currency`, `--category`, `--date`, `--account`, `--book`, `--paid-by`, `--shares` |
| `list --from 2026-10-01` | показывает записи |
| `edit 12 "category=кафе и доставка"` | меняет поля записи |
| `delete 12` | удаляет записи |
| `share 3,7,12-15` | проставляет расходам доли людей с расчётами |
| `report balance` | остатки по счетам и валютам |
| `report categories --month 2026-10` | расходы и доходы по категориям |
| `report debt` | кто кому должен |
| `report tax --book бизнес --period 2026-H2` | оценка налога книги |
| `check` | проверяет журнал, правила категорий и тесты расширений |
| `import-kaspi выписка.pdf --dry-run` | импорт выписки Kaspi Gold |
| `import ИМЯ ФАЙЛ --dry-run` | импорт файла импортёром из `extensions/` |
| `export --excel выгрузка.csv` | таблица для Excel |
| `ui` | страница-кабинет в браузере |
| `agents` | перестраивает блок основы в `AGENTS.md` по `settings.toml` |
| `restore` | копии журнала из `backups/` и возврат из копии |
| `update` | новая версия кода |
| `migrate --person KEY` | переводит журнал старой схемы на новую |

Флаги книг, счетов и расчётов появляются, когда они включены в `settings.toml`.
Полная справка: `py budget.py -h` и `py budget.py <команда> -h`.

## Настройки

```toml
schema = 2
code = "C:/Users/anya/budzheved"

[owner]
currency = "EUR"
country = "DE"

[books]
default = "личное"
names = ["личное", "бизнес"]

[accounts.card]
book = "личное"
currencies = ["EUR"]

[accounts.paypal]
book = "бизнес"
currencies = ["USD", "EUR"]

[people.boris]
name = "Борис"
role = "партнёр"          # партнёр | работник | поставщик | сервис | покупатель
settlements = true
default_share = 50

[tax."бизнес"]
rate = 3                  # процент, без знака %
base = "доходы"           # доходы | доходы-расходы
period = "полугодие"      # месяц | квартал | полугодие | год
categories = ["продажи"]

[categories]
expense = ["закупка товара", "доставка"]
income = ["продажи"]
```

Всё, кроме `schema`, `code` и `[owner]`, необязательно. Нет `[accounts]` — остатки
одной цифрой на валюту. Нет людей с `settlements = true` — доли и долги скрыты.
Нет `[tax]` — `report tax` отвечает, что налог не настроен. Ключи таблиц с
кириллицей пишутся в кавычках, в путях `/` вместо `\`. После правки:
`check`, затем `agents`.

## Налог

`report tax` — оценка: база и сумма по каждой валюте отдельно и список записей,
которые требуют решения человека. Это не декларация и не консультация: ставку и
правила своего режима человек сверяет сам.

## Обновление

`py budget.py update` из папки данных. Если папка кода — клон git, обновление идёт
через `git pull --ff-only`; иначе скачивается архив последнего выпуска, проверяется
и встаёт на место прежнего кода. Любой сбой до замены оставляет прежний код как
был. После обновления блок основы в `AGENTS.md` перестраивается новым кодом. Если
`update` просит `migrate`, это переход журнала на новую схему: он идёт со сверкой
отчётов до и после и откатывается при расхождении.

Папка данных не должна лежать внутри папки кода: `update` такую папку не тронет и
откажет.

## Без git

Git не обязателен. Код берётся архивом последнего выпуска: адрес архива лежит в
поле `zipball_url` ответа https://api.github.com/repos/ishaba/budzheved/releases/latest,
команды для PowerShell есть в промпте выше. `update` скачивает новый архив так же.
Если git не хранит журнал папки данных, перед каждой записью журнал копируется в
`backups/`, хранятся 30 последних копий:

```bash
py budget.py restore              # список копий, новые сверху
py budget.py restore ИМЯ          # вернуть журнал из копии
```

Перед возвратом текущий журнал тоже копируется. Если `journal.csv` уже добавлен в
git, копий нет: историю хранит git, а агент коммитит после каждого изменения.
Репозиторий где-то выше по папкам, который журнал не хранит, копии не отключает.

## Расширения

Свой импортёр выписки, отчёт или правило налога — файл `extensions/<имя>.py` в
папке данных с функцией `register(api)`:

```python
def register(api):
    api.importer("mybank", parse)  # parse(path) -> список словарей полей журнала
    api.report("закупки", report)  # report(entries, settings, args) -> str
    api.tax_rule("бизнес", rule)  # rule(entries, settings) -> ledger.tax.TaxResult
```

- Импортёр возвращает список записей или `{"entries": [...], "totals": {...}}`, где
  `totals` — итог движения по каждой валюте для сверки. Обязательные поля записи:
  `date`, `type`, `amount`, `currency`, `source_ref`. Основа проверяет записи,
  пропускает уже импортированные по `source_ref` и записывает остальные.
- Расширение не пишет в `journal.csv`, `settings.toml` и `merchants.csv` само.
  Изменение мимо основы откатывается, а расширение выключается.
- Ошибка в расширении выключает только его, с сообщением; остальное работает.
- На каждое расширение — тест `extensions/test_<имя>.py` на `unittest`. `check`
  запускает эти тесты.
- Отчёт расширения: `report <имя> [аргументы]`; импортёр: `import <имя> ФАЙЛ`.
- Агент ставит расширение только после «да» человека и записывает, что оно делает,
  в раздел `## Моё` файла `AGENTS.md`.

## Схема журнала

`journal.csv` — CSV в UTF-8 без BOM, схема 2. Колонки по порядку:

| Поле | Значение |
|---|---|
| `id` | номер записи; номер удалённой записи новой не достаётся |
| `date` | дата `ГГГГ-ММ-ДД` |
| `type` | тип операции, см. ниже |
| `book` | книга из `settings.toml`; пусто — книга счёта, а без счёта книга по умолчанию |
| `account` | счёт из настроек; пусто — «без счёта» |
| `amount` | сумма больше нуля; только у `expense` может быть отрицательной — это возврат; ноль не бывает |
| `currency` | код ISO из трёх букв или `USDT` |
| `account2` | второй счёт для `transfer` и `exchange` между счетами |
| `amount2`, `currency2` | вторая сторона обмена или зачёта долга |
| `category` | категория расхода или дохода |
| `description` | описание |
| `paid_by` | `me` или ключ человека с `settlements = true`: кто платил или кто кредитор |
| `party` | ключ человека или контрагента из `[people]` |
| `shares` | доли людей: `ключ:процент` через `;`, например `boris:50` или `anya:25;boris:25`; пусто — всё моё. Сумма долей не больше 100 |
| `tax` | `да` или `нет` вопреки правилу налога; пусто — по правилу |
| `source` | откуда запись: `text`, `screenshot`, `receipt`, `kaspi-pdf` или `import:<имя>` |
| `source_ref` | ссылка на строку выписки, по ней импорт находит дубли |
| `receipt` | путь к файлу внутри `receipts/` |
| `note` | примечание |

Типы: `expense`, `income`, `exchange`, `cash_withdrawal`, `transfer`, `settlement`,
`debt`, `debt_conversion`, `opening_balance`.

| Тип | Остаток | Расход / доход | Долг |
|---|---|---|---|
| `transfer` `account` → `account2` | −A на `account`, +A на `account2` | нет | нет |
| `cash_withdrawal` `account` → `account2` | −A на `account`, +A на `account2`; пустой `account2` — «без счёта» | нет | нет |
| `debt`, кредитор я | нет | нет | +A у `party` |
| `debt`, кредитор `party` | нет | нет | −A у `party` |

Остатки ведутся по паре «счёт, валюта», «без счёта» — тоже счёт; долг — по паре
«человек, валюта». `settlement`, `debt_conversion` и `debt` указывают человека в
`party`. `transfer` между счетами разных книг — вклад в книгу или изъятие из неё,
не доход и не расход ни одной из них. Журнал меняют только команды и страница
`ui`; руками его не правят.

## Ограничения

- Импорт Kaspi Gold зовёт `pdftotext` из Poppler. Нет его — понятная ошибка с
  подсказкой, остальное работает.
- Страница `ui` локальная: открывается на этом компьютере и не публикуется.
- Налог — оценка, см. выше.

## Разработка

- `python -m unittest discover -s tests` — тесты без зависимостей.
- `python scripts/smoke.py .` — первый запуск как у человека: копия кода без git,
  `init`, запись, отчёты, `check`.
- `./bin/verify` — формат, линт и тесты через uv.

`ledger/` держит код, `budget.py` — тонкий вход, `tests/` — тесты рядом по именам
модулей.
